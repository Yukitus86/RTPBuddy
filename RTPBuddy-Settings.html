RTPBuddy Settings

What every switch actually does — and when you should touch it.

Open the menu with O, the Options button on the map, or /rtpbuddy config. Everything lands in .minecraft/config/rtpbuddy/config.json.

The short version is in the game now: hover a switch and the tooltip explains it. This page is the long version. The /rtp command itself is not part of RTPBuddy — the server provides it; this mod only watches what you type and where you end up.

Capture

Tab 1

Controls how RTPBuddy notices a teleport and records it. These are the switches that decide whether an RTP makes it onto the map at all.

Capture

capture.enabled on

Master switch for automatic recording. Off means typed commands are no longer watched and no new samples appear. Existing data is untouched.

Manual capture with K keeps working — it does not go through this check.

Capture on commands

capture.autoCapture on

Whether a matching command arms a capture. Off means you only record by hand with K. Useful when a server uses commands whose patterns keep misfiring.

On dimension change

capture.captureOnDimensionChange on

Counts a dimension change during the waiting phase as a successful teleport.

This is the switch for /rtp nether and /rtp end. Crossing into another dimension can move you a tiny horizontal distance — without this switch only the distance threshold applies, and those RTPs end up in the "missed" counter.

Reject short jumps

capture.rejectShortJumps on

Checks after landing: if the horizontal jump is below the teleport threshold and the dimension stayed the same, the sample is thrown away (the "rejected" counter).

Keeps a refused RTP — server says no, you are still standing there — out of the statistics.

Write CSV mirror

capture.writeCsvMirror on

Keeps rtp_samples.csv in step with the JSON. The JSON is authoritative; the CSV is pure convenience for Excel and friends. Off saves writes.

Teleport threshold

capture.teleportDistanceThreshold 200 blocks

The horizontal distance at which a position jump counts as a teleport.

Too low: elytra flight or a nether portal trigger false readings. Too high: nearby RTPs are not recognised as teleports at all.

The same number decides what "Reject short jumps" considers too short.

Steps  50 · 100 · 200 · 500 · 1000 · 2000

Arm timeout

capture.armTimeoutTicks 15 s

How long to wait for the teleport after the command. When the time runs out the capture quietly disarms and the "missed" counter goes up by one.

Raise it if your server has a countdown ("teleporting in 3… 2… 1…"). 15 s is enough for an instant RTP, not for a 30 second warm-up.

Steps  5 · 10 · 15 · 30 · 60 s

Settle time

capture.settleTicks 10 ticks

After the jump is seen, the position has to hold still for this many ticks before the sample is taken. Still means under 0.05 blocks of drift per tick — any real movement resets the count to zero.

Stops a server-side correction from being recorded as the final position. Set it to 0 only if you want to run off immediately and the last decimal does not matter.

Steps  0 · 5 · 10 · 20 · 40 ticks   ·  20 ticks = 1 second

Save debounce

capture.saveDebounceMillis 2000 ms

Batches writes: a run of RTPs collapses into a single write to disk.

0 writes immediately — more disk activity, but no window of loss. After a crash you lose at most the samples from that window; the file itself can never be left half written (temp file plus rename).

Steps  0 · 1000 · 2000 · 5000 · 10000 ms

Record unknown /rtp

capture.captureUnknownRtp on

Also records an /rtp whose destination is missing from the region list. The argument is kept verbatim as the requested region (/rtp mars → region mars) rather than being mapped onto the nearest configured one. Without this, such a landing is dropped in silence.

What counts as an RTP command is capture.rtpCommandPattern. Other commands such as /tpa trigger nothing.

Reapply DonutSMP preset

Action

Not a switch: resets the region list to the bundled preset — overworld, nether, end plus the six server zones asia, east, west, eu central, eu west and oceania, with their patterns and commands.

Use it when you have broken the patterns editing config.json. The Regions: line at the bottom of the tab shows what is loaded and marks bad patterns with (bad pattern).

Auto-RTP

Tab 2

The loop that repeats /rtp for you. Off after every start of the game; the running state is never written to disk.

Start Auto-RTP… / Stop

Action

Opens the start dialog. It names the whole rotation, the wait with its jitter and every condition that will end the run — nothing is sent before you press Start Auto-RTP. The button stays greyed out only when no chosen region has a command, because then the loop would send nothing.

Hold / continue Auto-RTP

Action

Only offered while a run exists. Holding does not end it: nothing is sent, the wait and the run timer both freeze, and damage or a guard violation stop nothing while it holds. Continuing picks up with the wait that was left when you held it — same counters, same position in the region rotation.

It is for stopping to look at wherever the last teleport landed, without losing the run. Key H, in chat /rtpbuddy auto pause and /rtpbuddy auto resume. On the map the auto button then reads Auto held instead of a frozen countdown.

Regions

autoRtp.regions empty

One switch per configured region, captioned with the command that is actually sent (Asia  /rtp asia). Ticked means this region is part of the run.

With several on, each teleport takes the next one — /rtp asia, cooldown, /rtp eu central, cooldown, /rtp east, then round again. On a server where a plain /rtp keeps handing back the same zone, this is the only way to fill in the rest of the map. The full rotation is written out under the switches and again in the start dialog.

With none ticked, autoRtp.region still applies (default overworld), so an older config behaves exactly as before.

Order

autoRtp.order Round robin

Only shown when more than one region is on. Round robin walks the list in order so every zone gets the same number of samples; Random picks one each time.

Cooldown

autoRtp.cooldownSeconds 60 s

Gap between two teleports, typed in seconds — no fixed ladder of steps any more, because no ladder hits the interval a given server actually wants. Hard-floored at 2 s.

Measured between landings, not between sends. A slow teleport therefore pushes the next command back instead of queueing commands up.

It never shortens a server cooldown: if the server refuses, the next attempt simply waits the same interval again.

Jitter

autoRtp.jitterSeconds +0–5 s

A random 0 to n seconds added to every cooldown, so the spacing is not machine-exact. Typed freely as well; 0 turns it off.

Trigger by hand

autoRtp.manualStep off

Turns the clock off. The run stays a run — the rotation, the counters, the caps, the run timer and every stop condition behave exactly as they do on the timer — but nothing is sent until you press the auto-RTP key, one teleport per press.

It is for the other half of the job: filling a map and looking at where you landed want different rhythms, and the second one is yours to set rather than a rate you had to guess in advance.

Cooldown and jitter no longer apply, bar a hard floor of 2 seconds between commands — a held key must not turn into a command every tick. There is no countdown, so none is shown: the HUD reads MANUAL and the map button Auto manual.

A press that cannot be honoured refuses rather than queues, and says why: the last landing is still being recorded, the floor has not elapsed, the run is held. A teleport fired silently later would be worse than none at all — knowing when the command went out is the entire point of stepping by hand. A press that worked says nothing: the command is already in the chat, the server answers it, and the HUD counts it. /rtpbuddy auto step does the same from chat.

Stop after

autoRtp.stopAfterMinutes 30 min

Wall-clock limit for one run.

Steps  no limit · 10 · 30 · 60 · 120 min

Max per run

autoRtp.maxPerSession no limit

Ceiling on teleports per run.

Steps  no limit · 25 · 50 · 100 · 250 · 500

Wait for the landing

autoRtp.waitForCapture on

While a capture is still running (armed or settling), the cooldown restarts instead of the next command being sent.

Leave it on while you are recording — otherwise the loop overtakes its own measurement.

Stop on damage

autoRtp.stopOnDamage on

Halts the moment your health drops. The one switch that keeps an unattended run from killing you.

Stop outside the guards

autoRtp.stopOnGuardViolation off

Halts when a landing falls outside the border buffer or inside the spawn buffer. Only turn this on once the values in the Guards tab really match your server — otherwise the loop stops for no reason.

Stop on nearby player

autoRtp.stopOnPlayerNearby off

Ends the run as soon as another player turns up inside the radius, with a bell and the distance in chat — a stop that only reaches a screen you were not watching warns nobody.

It takes effect only once the run has teleported you away: a jump past the capture threshold, or a change of dimension. That is not a limitation, it is what makes the setting usable. It fires because a landing put someone next to you — and that someone is still there afterwards. Live from the first tick, the run you start to get away would die on the very player you are getting away from. Whoever is next to you when you press start is your business; whoever is next to you where the loop dropped you is the loop’s.

It reads the client’s own player list, which is exactly what the server sent. Anyone outside the server’s tracking range, and anyone it is hiding, does not show up here. A reason to stop, not a promise that you are alone.

Player radius

autoRtp.playerNearbyRadius 64 blocks

How close another player has to be to count, measured in three dimensions: 16 · 32 · 64 · 128 · 256 blocks. Setting it beyond your server’s tracking range buys nothing — players further out never reach the client at all. Spectators do not count.

Search order

autoRtp.findEnabled off

Every stop above ends a run because something went wrong. This one ends it because the run found what it was sent out for: it keeps teleporting until a landing matches, stops on that landing, plays a short bell and says in chat which condition fired.

It never sends more, faster or differently. A search order can only end a run earlier than it would have ended anyway. While the switch is off, nothing below it is built at all.

New cell

autoRtp.findNewCell off

Stops on the first landing in a cell no recorded landing has ever reached. This is the condition that fills the cell board — exactly the teleports that get you somewhere.

Named cells

autoRtp.findCells empty

A typed list such as 11 12 20. Separators do not matter; anything that is not a number from 1 to 81 is dropped rather than rejected — the field is typed into, and a half-finished entry must not break the whole order.

Distance from / to

autoRtp.findMinDistance / …MaxDistance 0 / 0

A band measured from the world origin. 0 switches the respective bound off.

Target X / Z

autoRtp.findNearX / …NearZ 0 / 0

The point the run should stop near. Only takes effect with a radius. Target = my position takes your coordinates and puts the radius at 500 if none is set yet.

Target radius

autoRtp.findNearRadius 0

Stops as soon as a landing falls closer than this to the target point. 0 switches the condition off.

Biomes

autoRtp.findFamilies / …findBiomes empty

Eighteen rows, one per family, from Plains to Rare. A click opens the biomes behind it: the whole family on top — stops on any landing in that colour — and under it every single biome with the number of landings already recorded in it. Several may be ticked at once, in one family or across many, and the menu stays open while you tick them.

The list comes from the server's own biome registry, not from your landings: otherwise the one thing you are looking for would be the one thing missing from it. That makes the 0 behind a biome the interesting number — that is where the search has never been. Pale Garden rather than something rare.

Combine

autoRtp.findMatchAll any one

Whether one satisfied condition is enough or they all have to hold at once. All together gets rare quickly — that is when the give-up cap earns its keep.

Give up after

autoRtp.findGiveUpAfter no limit

Ends the run after this many landings with no match. With no cap a search order for a rare target runs until something else stops it — exactly the sort of thing that should not be a default.

Sound on a match

autoRtp.findSound on

A short bell when the order fires. The whole point of a search order is not having to watch, so the ending has to arrive without a look at the screen. While a run is searching, the HUD says what it is looking for and how many landings it has turned down.

Always, with no switch involved, the loop stops on: disconnect, world change, the End key, and /rtpbuddy auto stop.

H is deliberately not in that list while a run is on the clock: it holds, it does not stop. A held run stays alive and waits for you.

Guards

Tab 3

These values describe your server's map. They never block a capture. What they do drive: overlays on the map, a warning on the sample, the coverage statistic, and optionally the auto-RTP stop from tab 2.

Border radius

guards.borderRadius 30,000,000

Radius of the overworld border in blocks, measured from the border centre. The default is the vanilla limit; on an SMP you put the real value here. For DonutSMP that is 225,000 — the border sits 225,000 blocks from 0,0 in every direction, so the world is 450,000 × 450,000 blocks. Leave Square border on as well. The nether and the end have borders of their own — see guards.netherBorderRadius and guards.endBorderRadius, which for DonutSMP are 28,500 and 87,500. Each dimension gets its own rectangle on the map, in that dimension's colour.

It is also the basis of the coverage statistic: density cells hit, divided by the cells inside the border.

Border buffer

guards.borderGuard 1000

Safety margin inwards. Usable area = radius − buffer. That inner edge is exactly what gets drawn on the map and checked for the warning.

Spawn X · Spawn Z

guards.spawnX / spawnZ 0 / 0

Centre of the spawn zone.

Spawn buffer

guards.spawnGuard 500

Radius around that point that counts as "too close to spawn".

Square border

guards.squareBorder on

Treats the border as a square (like vanilla) rather than a circle. Changes the shape of the overlay and the area formula behind the coverage statistic.

Use my position as spawn

Action

Takes your current X/Z as the spawn centre.

In config.json only: guards.borderCenterX and guards.borderCenterZ — the centre of the world border, if your server is not centred on 0/0.

On numbering: samples count from 1 within a sitting. A new session starts at #1 again rather than carrying on from the number reached yesterday.

What decides it is the plot, not the scope: tick a single sitting in All sessions and it counts from 1 there too. Only once two sittings share the plot does the global number take over — it is then the only one that stays unique, and it is what the CSV, the viewer and the delete dialog mean. Not a setting, and the stored number never changes either way.

On the density cell: it draws nothing as of 1.6.8 — the heatmap is gone — but it is still the basis of the coverage statistic: cells hit divided by the cells inside the border. Smaller cells measure finer but push the coverage percentage down — at 130 samples with 512-block cells it is already only 0.000 %.

So pin the cell size before comparing that percentage, or you are comparing apples with oranges.

On the frame cap: Minecraft does not throttle a screen while a world is behind it, so the map redraws as fast as your video setting allows. The picture only changes when you move the mouse, so the spare frames buy nothing and heat the CPU. Set it to off if you would rather let the video setting decide.

On the Advanced mode: it asks the opposite question — not where the landings are, but where they are not. Every point of the plot is shaded by its distance to the nearest landing; bright means far from everything. Up to the 2k scale it shades, past it it counts fixed world tiles in four bands — the switch sat at 5k until 1.6.20, but by a 5k scale bar the squares already say more than the shading does. The biggest holes are listed with coordinates and radius in the metrics column, the radius always rounded down: the patch is at least that empty.

Filter to one region first. The measurement handles overlap correctly on its own — a spot two regions reach is only rare if it is rare in both. But a hole in the region you care about will be filled in by landings of a region you never asked for there.

Two rules keep the tiles honest while the view moves. The mask is asked in world units, never through a screen pixel: asked through the clipped centre of a tile hanging off the edge, the outer row and column blinked in and out on a drag, because the probe walked across the tile while the tile stood still. And a tile holding a landing is drawn whatever the mask says — a marker sitting on bare ground with no tile under it reads as a bug.

A hole at the frontier of the recording is still listed. The field goes on rising into unexplored ground, so no cell inside the mask is a local maximum there; a neighbour outside the mask therefore does not count as higher. Without that, the biggest hole on the map is the one that goes missing from the list.

HUD

Tab 5

The two overlays while you play: the text readout with capture state, counters and last sample, and the minimap. They have a tab of their own because the game screen is shared: RTPBuddy has no say over what other mods draw in the top left or the top right, so its own readouts have to be movable to wherever there is room.

Minimap

The small map at the edge of the screen. It frames exactly the rectangle the full map's F picks — the chosen landings, framed — with your own position inside it. The frame is fixed: it does not scroll with you, because a map that recentres on every step says nothing about where you are within the recording. Walk out of the rectangle and your marker is pinned to the rim in amber. With nothing recorded it frames the server cell you are standing in instead.

On the frame cost. The plate is painted once into a texture and then drawn as a single quad. A thousand landings would otherwise be a thousand fill calls in every single frame — the mistake the gap map very nearly shipped with, made permanent, because a minimap is on screen for the whole session. It is repainted only when the picture actually changes: a new landing, a different sitting, a switch flipped, or crossing into another server cell. Such a repaint measures under 3 ms with two thousand landings on it. What is left per frame is your marker, up to sixteen cell numbers and the caption — some fifty rectangles, about what one vanilla HUD widget costs.

Not saved settings in the strict sense, but the same kind of switch — the config remembers the first two and the scope.

ButtonEffect
Points / Path / AdvancedHow samples are drawn. Points draws solid markers and nothing else — no lines. Path draws the route in recording order, one pixel wide, with a direction chevron per segment and hollow markers behind it. Advanced — the gap map — drops the landings as the subject and shades the distance to the nearest one instead, so the empty ground is what the eye lands on
Dimension / Region / Recency / Session / BiomeWhat the marker colour means. Biome paints by biome family — close to fifty biomes are recorded, and fifty hues on one plot is confetti
All biomes / Forest / Plains / …Drops down the biome families the chosen scope actually holds, each with its colour and its count, All biomes on top. One click picks, a click beside it closes, and so does Esc. Cycling eighteen families would not be a filter: after the wrong pick there would be seventeen clicks between you and all of them again. A single biome is what the search box is for — it matches both the id and the name the game shows

This session / All sessions (top right)The scope. In All sessions the session list appears in the sidebar; unticking rows there hides individual sittings and the button reads Picked (n)
Start a new sitting (in the session card)Closes the sitting in progress and opens the next one without relogging. Sample numbers start at 1 again and the card's counters reset with them. Nothing is deleted: the landings recorded so far keep their sitting. A sitting with no landing is left alone
Delete empty sessions (n) (in the session list)Shown only while there are sittings with no landing at all, and deletes exactly those. The running sitting is never among them, and samples are never touched

Options OThis settings menu
Auto off / Auto 42s / Auto heldStarts or stops the auto-RTP loop, and doubles as the countdown. With the run held by H it reads Auto held — a countdown that never moves would look like a stuck game
Rename session (in the session list)Appears as soon as exactly one sitting is ticked — the running one included. Gives it a name of its own, up to 32 characters, instead of every row repeating the server address. The name then shows in the session list, in the session card and in the viewer; leave it empty to clear it back to the server name. It is stored as label on the session record and touches none of the landings
Merge sessions (n) (in the session list)Appears as soon as two or more sittings are ticked. Folds them into one: the target is the oldest, whose colour, name and start time stay, and its span widens to cover them all. Nothing is deleted — every landing survives, it just belongs to one sitting now, and the numbers run from 1 in the order you actually landed. The other session records go, which is why a dialog asks first; it cannot be undone. Refused across servers. If the running sitting was among them, it carries on inside the merged one
Continue session: DD-MM HH:MM (in the session list)Appears as soon as exactly one sitting is ticked and it is not the running one — so after None and a click on a row. Continues that sitting instead of opening a new one: every further landing takes its number, so the count carries on rather than restarting at 1, and the HUD counts on from that sitting's total. The sitting in progress is closed first — and discarded if it recorded nothing. Refused across servers: a sitting is one stretch of play on one server, and two of them in a single run of numbers would be a lie
